# HypeCheck

Paste a stock post, get each claim checked against public filings.

```
packages/check-core   the pipeline: claim extraction, data sources, comparison, shared types
apps/api              one endpoint, POST /api/check, plus a command-line checker
apps/web              phone-first React app (home, results, receipt)
docs/decisions.md     why it is built this way, and what it can't do yet
```

## Run it

Requires Node 20 or newer.

```bash
npm install

# 1. Demo mode: a made-up company (TGSR), no network, no keys.
npm run dev:demo          # then open http://localhost:5173 and tap "Try an example post"
npm run check:demo        # same check, in the terminal

# 2. Live mode: real companies, real SEC filings.
cp .env.example .env      # then set SEC_USER_AGENT to your name and email
npm run dev
npm run check -- "\$AAPL revenue is up 300% this quarter"
```

Add `ANTHROPIC_API_KEY` to `.env` to have an LLM read the post. Without it, a small
rule-based extractor is used, which only understands phrasings like "revenue is up 40%".

```bash
npm test                  # pipeline tests
npm run typecheck
npm run build             # production build of the web app
```

## Deploy (Vercel)

The repo deploys as one Vercel project: the web app is static (`apps/web/dist`) and
`api/check.js` is a serverless function, so the app and its API share one URL.
`api/check.js` is generated by `npm run build:api` from `apps/api/src/vercel.ts`; the
build regenerates it, but commit it after changing anything in `packages/check-core`.

1. Push the repo to GitHub.
2. In Vercel: Add New > Project > import the repo. Leave Root Directory as the repo root;
   `vercel.json` sets the build.
3. Settings > Environment Variables:
   - `SEC_USER_AGENT` = `HypeCheck your-email@example.com` (required for live data)
   - `ANTHROPIC_API_KEY` (optional; without it the rule-based extractor is used)
   - or `HYPECHECK_DEMO` = `1` to serve only the made-up demo company
4. Redeploy after changing variables.

The public link calls the LLM on every check, so set a spending limit on the API key.

## How a check works

1. **Extract (LLM).** The post goes in, a list of claims comes out: quote, type, ticker, figure.
2. **Route (code).** Each claim goes to the data source that supports its type.
3. **Fetch (code).** The source pulls evidence from the SEC. Evidence is cached per company.
4. **Compare (code).** The claimed figure is compared with the filed one, and a verdict and a
   plain-language reason are built from the numbers.

The LLM never supplies a fact, a number or a verdict.

## Adding a data source

Create a file in `packages/check-core/src/sources/` that implements `EvidenceSource`
(`supports`, `cacheKey`, `fetchEvidence`, `evaluate`), add its evidence shape to the
`Evidence` union in `types.ts`, and register it in `apps/api/src/checker.ts`.
`sources/sec/revenueSource.ts` is the worked example.

## What it checks today

Against the company's own SEC filings:

- Revenue growth: "revenue is up 300%"
- Reported dollar figures: "Q2 revenue of $11.5B", "a $42M net loss"

Short interest, deals, insider trades and other dollar figures are recognised but come back as
"can't be checked". So does anything about a private company, since it has no filings.
See `docs/decisions.md` for the list of known limits.
